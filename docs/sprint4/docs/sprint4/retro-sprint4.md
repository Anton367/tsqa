## Start / Stop / Continue

### Start (Почати робити)
1. **Проводити крос-перевірку артефактів до фінального коміту в `main`:** звіряти ID вимог, назви класів, файлів та статистику між `README.md`, `coverage-matrix.md`, `ui-scenarios.md` і `surefire-summary.md` перед закриттям Pull Request.
2. **Одразу прив'язувати червоні тести до GitHub Issues:** при виявленні падіння спочатку звіряти очікуване значення з `SRS-1.1.docx`, оформлювати Issue з виводом Surefire і вказувати його номер у коментарі над тестовим методом.
3. **Запускати повний прогін у чистому середовищі перед демо:** перевіряти відтворюваність `mvn clean test` та `mvn test -DexcludedGroups=none` на машині іншого учасника за інструкцією `README.md`.

### Stop (Припинити робити)
1. **Припинити формальне рецензування «заднім числом»:** не ставити позначку «Reviewed / Approved» без перевірки за чек-листом, конкретних коментарів та підтверджених виправлень.
2. **Припинити дублювання або змішування контурів збірки:** не залишати чернетки експорту Selenium IDE (JUnit 4) у каталогах компіляції Maven та не змішувати локальні тести без `@Tag("ui")` із регресійним юніт-набором.
3. **Припинити «підганяти» очікувані результати під фактичний код:** залишати падаючі тести відкритими як фіксацію дефектів v1 для регресійної перевірки на версії v2 у Спринті 5.

### Continue (Продовжувати робити)
1. **Чіткий розподіл відповідальності та фіксація внеску в Git:** кожен учасник самостійно реалізує свою частину тестів і бере участь у взаємному рецензуванні.
2. **Використання параметризованих тестів і явних очікувань:** систематично застосовувати `@ParameterizedTest` + `@CsvSource` для граничних значень (з обох боків меж) та `WebDriverWait` замість `Thread.sleep` у UI-тестах.
3. **Оперативна синхронізація в командному чаті:** швидко вирішувати відкриті питання щодо розбіжностей між специфікацією та кодом за участю Керівника тестування і Тест-аналітика.
