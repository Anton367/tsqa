# Протокол внутрішнього рецензування артефактів (Спринт 1)
**Продукт:** «ФінКит»
**Рецензенти:** Дарія (Скрам-майстер), Ліза (Тест-аналітик)
**Дата:** 28.09.2026

## 1. Рецензія на моделі бізнес-процесів BPMN 2.0
**Автор моделей:** Антон
**Перевірено за:** Чек-листом коректності нотації BPMN (10 пунктів).

*   **Модель «Переказ коштів» (`01_transfer.drawio`)**
    *   **Дефект (п. 3 чек-листу):** Потік управління (суцільна стрілка) перетинав межу пулів між учасниками «Клієнт» та «Банк».
    *   **Дефект (п. 5 чек-листу):** Після розгалуження (AND) гілки сходилися у дію без синхронізуючого шлюзу.
    *   **Виправлення:** Суцільну стрілку між пулами замінено на пунктирний потік повідомлень. Додано закриваючий паралельний шлюз (AND) перед дією запису в історію.
    *   **Статус:** Виправлено, прийнято.

*   **Модель «Оформлення кредиту» (`02_loan.drawio`)**
    *   **Дефект (п. 7 чек-листу):** Шлюз розгалуження мав назву дії («Перевірка результату скорингу»).
    *   **Виправлення:** Назву шлюзу змінено на запитання згідно з нотацією («Який результат скорингу?»).
    *   **Статус:** Виправлено, прийнято.

*   **Модель «Відкриття рахунку» (`03_account.drawio`)**
    *   **Результат:** Дефектів не виявлено, модель повністю відповідає чек-листу.
    *   **Статус:** Прийнято.

## 2. Рецензія на Беклог вимог (User Stories)
**Автор беклогу:** Ліза
**Перевірено за:** Шаблоном User Story та покриттям ролей з легенди продукту.

*   **Дефект (Критерій ролей):** В історіях US-05, US-08 та US-11 використовувалася роль «Система», що порушує нотацію (роль має належати живому стейкхолдеру з легенди). Також беклог не покривав жодної взаємодії для ролі «Операціоніст».
*   **Виправлення:** Системні історії переписані від імені реального користувача («Адміністратор»). Додано нову історію (US-13), яка описує взаємодію Операціоніста із заявками.
*   **Статус:** Виправлено, прийнято.
