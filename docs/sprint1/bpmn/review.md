## 1. Рецензія на моделі бізнес-процесів BPMN 2.0
**Автор моделей:** Антон
**Перевірено за:** Чек-листом коректності нотації BPMN (10 пунктів).

*   **Модель «Переказ коштів» (`01_transfer.bpmn`)**
    *   **Перевірка:** Перевірено: п.1–10 ✓ (дефекти виправлено).
    *   **Дефект (п. 3, 5, 8, 10):** Потік управління перетинав межі пулів між клієнтом і банком. Для одночасного списання/зарахування використовувався шлюз включного АБО замість паралельного (ТА), розгалуження не було закрите. Кінцеві події відмови не містили повідомлень клієнту. Відсутні артефакти даних.
    *   **Виправлення:** Суцільні стрілки між пулами замінено на потоки повідомлень. Шлюзи змінено на паралельні (ТА) із відповідним закриваючим шлюзом. Кінцеві події відхилення змінено на кінцеві події-повідомлення. Додано артефакти даних з асоціаціями.
    *   **Статус:** Виправлено, прийнято.

*   **Модель «Оформлення кредиту» (`02_loan.bpmn`)**
    *   **Перевірка:** Перевірено: п.1–10 ✓ (дефекти виправлено).
    *   **Дефект (п. 4, 7, 8, 10):** Шлюз розгалуження мав назву дії («Перевірка результату скорингу»). Очікування підтвердження від клієнта змодельовано звичайним XOR замість шлюзу за подіями. Кінцеві події відмови не містили повідомлення клієнту. Відсутні артефакти даних (наприклад, «Заявка на кредит»).
    *   **Виправлення:** Назву шлюзу змінено на запитання. Розгалуження для очікування замінено на шлюз за подіями (гілка події-повідомлення від клієнта та гілка події-таймера на 7 днів). Кінцеві події відмови змінено на події-повідомлення. Додано артефакт даних.
    *   **Статус:** Виправлено, прийнято.

*   **Модель «Відкриття рахунку» (`03_account.bpmn`)**
    *   **Перевірка:** Перевірено: п.1–10 ✓ (дефекти виправлено).
    *   **Дефект (п. 8, 10):** Відсутній артефакт даних «Реєстр клієнтів», заявлений у таблиці елементів. Кінцева подія відмови не відправляла повідомлення.
    *   **Виправлення:** Додано артефакт даних та асоціацію до відповідної задачі. Кінцеву подію відмови замінено на подію-повідомлення.
    *   **Статус:** Виправлено, прийнято.

## 2. Рецензія на Беклог вимог (User Stories)
**Автор беклогу:** Ліза
**Перевірено за:** Шаблоном User Story, критерієм простежуваності та покриттям ролей з легенди.

*   **Перевірка:** Перевірено відповідність формату та простежуваність до замовлення.
*   **Дефект (Критерій ролей та простежуваність):** В історіях US-05, US-08 та US-11 використовувалася роль «Система». Відсутні історії для ролі «Операціоніст». Очікування замовника №2 (графік за місяцями) не покрито жодною сторі. Відсутній аркуш для матриці простежуваності «Очікування → stories».
*   **Виправлення:** Системні історії переписані від імені реальних стейкхолдерів (Адміністратор/Клієнт). Додано історії для Операціоніста та окрему сторі для покриття графіка платежів. Створено окремий аркуш «Очікування → stories», простежуваність перевірена і працює в обидва боки.
*   **Статус:** Виправлено, прийнято.
